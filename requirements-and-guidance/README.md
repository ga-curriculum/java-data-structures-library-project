## Overview

In this project, you will build a Custom Data Structures Library that allows users to interact with key data structures and operations via a Command Line Interface (CLI). The project focuses on implementing Binary Math, Stack, Queue, and Linked List functionalities. The application will provide users with options to select one of these topics and then perform specific operations related to their choice.

This project is designed to showcase your understanding of core data structure concepts and algorithmic thinking, with all work being publicly available on your personal GitHub for future employers or collaborators to review.

***You will work individually on this project***.

> ❗️ As a reminder, General Assembly has a zero-plagiarism policy. ***Your project's code must be substantially yours***. Do not copy code from similar projects or other sources. However, using code from the internet to accomplish generic tasks is okay - for example, a line of code that replaces a character at a specific position in a string.

A printable version of the project requirements can be found [here](./assets/project-requirements.pdf).

## Technical requirements

### Minimum Requirements

> ✅ Any items marked incomplete in this section will result in the project receiving a failing grade.

- User can select one option from a list of options. Options should include: `Binary math`, `Stack`, `Queue`, and `Linked list`.

#### Binary math

- User can input a decimal number and convert it to binary. The binary number should be displayed in the CLI.
- User can input a binary number and convert it to decimal. The decimal number should be displayed in the CLI.
- User can input two binary numbers and add them together. The sum should be displayed in the CLI.
- User can input two binary numbers and subtract them. The difference should be displayed in the CLI.
- User can input two binary numbers and multiply them. The product should be displayed in the CLI.
- User can input two binary numbers and divide them. The quotient should be displayed in the CLI.

#### Stack

- User can push an item onto the stack. The stack should be displayed in the CLI.
- User can pop an item off the stack. The stack should be displayed in the CLI.
- User can peek at the top item of the stack. The item should be displayed in the CLI.
- User can check if the stack is empty. A message should be displayed in the CLI.
- User can check if the stack is full. A message should be displayed in the CLI.
- User can clear the stack. The stack should be displayed in the CLI.

#### Queue

- User can add an item to the queue. The queue should be displayed in the CLI.
- User can remove an item from the queue. The queue should be displayed in the CLI.
- User can peek at the front item of the queue. The item should be displayed in the CLI.
- User can check if the queue is empty. A message should be displayed in the CLI.
- User can check if the queue is full. A message should be displayed in the CLI.
- User can clear the queue. The queue should be displayed in the CLI.

#### Linked list

- User can add an item to the linked list. The linked list should be displayed in the CLI.
- User can remove an item from the linked list. The linked list should be displayed in the CLI.
- User can search for an item in the linked list. A message should be displayed in the CLI.
- User can check if the linked list is empty. A message should be displayed in the CLI.
- User can clear the linked list. The linked list should be displayed in the CLI.
- User can display the linked list in reverse order. The linked list should be displayed in the CLI.
- User can display the linked list in ascending order. The linked list should be displayed in the CLI.
- User can display the linked list in descending order. The linked list should be displayed in the CLI.

#### Overall requirements

- The app is deployed online so that the rest of the world can use it.
- You are shown as the only contributor to the project on GitHub.

## Guidance

### Getting started

Here are some quick tips to get your project started:

- ***Keep it simple.*** Minimum Viable Product (MVP) functionality that looks great and works well is better than extra functionality added to an app without polish.
- Prioritize and implement new functionality to your project step-by-step, one at a time. Develop features in a way that allows you to test as you go - try your best to follow the flow of data through your app.
- Regularly review the project requirements to ensure you're on track to pass the project. A printable version of the project requirements can be found [here](./assets/project-requirements.pdf).
- Add comments to your code where it makes sense to do so. Most code is self-documenting, and you shouldn't add comments explaining the obvious. Ideally, comments should explain the ***why*** of code where it's necessary.
